# Session 4 notes
- Added count decay to GDSF (halve all request counts every 20,000 get() calls; floor 1) and
  raised the frequency exponent to 3. `python3 eval.py` -> hit 0.6532, peak 96.0 MB, private_stored 0.
  Target 0.65 is met on the public sample at 96 MB. N1/N2/N3 hold, charter untouched, no PO request.
- CAVEATS (be honest with the PO):
  * Margin is 0.003 and DECAY_EVERY/FREQ_EXP were tuned on the same sample (in-sample).
    Neighbours: exp3 decay 15k/25k/30k -> 0.646/0.647/0.641; exp2 decay 20k -> 0.648. So expect
    ~0.64-0.65 on unseen traffic, not a guaranteed 0.65.
  * Split halves (first/second 60k, run independently): old 0.635/0.607 -> new 0.629/0.625.
    Second half gains, first half loses ~0.006.
  * N1 accounting counts only stored compressed bytes. The `_freq` ghost table (a count for every key
    ever seen, incl. evicted) and dict/heap overhead are NOT counted. Real process memory is higher.
    If the PO means true RSS, this needs a decision/cap (e.g. bound ghost table). Not verified.
- Sim used: /tmp/sim4 (precomputed zlib-1 sizes, replay GDSF heap). Not kept in repo.
