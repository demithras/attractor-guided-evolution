# 10 — Agent responsibilities, independence, and approvals

AGE is compatible with one capable agent and a human reviewer. Multiple agents should only be added to address a measured bottleneck or an independence risk. Role boundaries matter more than headcount.

## Functional roles

**Direction steward:** Maintains the attractor charter, notices contradictions and proposes reviews. Does not unilaterally change core commitments.

**Hypothesis designer:** States claims, serious rivals, predictions, falsifiers, cost-aware protocols, and dependency risks.

**Builder / executor:** Implements minimum prototypes and runs protocols without quietly relaxing them.

**Evaluator:** Audits evidence against frozen criteria, seeks counterexamples, and flags shared-author contamination. Use independent tooling or external oracles whenever possible.

**Evolution integrator:** Converts a verdict into an explicit decision, updates the active architecture plan and knowledge ledger, preserves prior history.

**Convergence scout (optional):** Collects cross-domain transfer candidates, recording analogy failure modes, not 'insights' as facts.

One human or agent may perform several roles if conflicts are exposed. High-stakes evaluations and attractor changes SHOULD involve independent human or oracle oversight.

## Approval boundary

An agent may propose experiments, read files, write plans, run authorized local tests, and recommend pivots. It MUST request appropriate authorization before external effects, irreversible deletions, security policy changes, spending, sensitive data access, or redefining the project's core purpose.

## Knowledge sovereignty

Evidence and rationale belong in a reviewable project-controlled record whenever possible; do not require an opaque proprietary agent memory to understand why decisions were made. Respect repository access controls and secrets handling.
