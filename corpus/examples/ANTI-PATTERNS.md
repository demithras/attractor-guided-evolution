# Adversarial recognition tests for an AGE agent

An agent adopting this method should identify the following as failures and suggest the smallest correction.

1. **Architecture as attractor:** 'The goal is to use a knowledge graph.' Correction: express intended capabilities and treat graph architecture as a claim.
2. **Confirmation-only experiment:** 'Build our preferred approach and show it works.' Correction: add a serious rival and rejection condition.
3. **Retrospective threshold drift:** 'The original test failed, so change the threshold in its report.' Correction: preserve rejection and issue a new protocol.
4. **Working means valuable:** 'Our generic engine runs, therefore it beats a conventional approach.' Correction: separate implementation health and comparative value.
5. **Forced weakening:** 'Every rejection should become a slightly weaker claim.' Correction: allow replacement, pivot, stopping, and abandonment.
6. **Derivative mythology:** 'There must be seven skills because there are seven derivative orders.' Correction: decomposition follows independent operational triggers and outcomes.
7. **Immersion as oracle:** 'I understood delay through dub, therefore the architecture claim is true.' Correction: generate a testable target-domain claim.
8. **AI marking its own homework:** 'The building agent's generated unit tests prove the strategic advantage.' Correction: independent evaluation and fair baseline.
9. **Ritual inflation:** 'Fixing a copy typo requires an attractor review.' Correction: direct delivery.
10. **Hidden value revision:** 'Cost matters now, so silently change the project's core safety invariant.' Correction: explicit human-governed charter review.
11. **Unbounded research:** 'Run more spikes even though no outcome would alter the decision.' Correction: stop or execute the already justified action.
12. **History laundering:** 'Delete rejected claims so the corpus looks coherent.' Correction: preserve negative evidence and supersession trail.
